## Acesso a bancos de dados

### 1. Introdução
O documento aborda a integração de bancos de dados em aplicações orientadas a objetos, destacando a importância da persistência de dados. O Entity Framework (EF) é apresentado como a principal ferramenta ORM (Object-Relational Mapper) do .NET, permitindo trabalhar com objetos de domínio enquanto abstrai a comunicação com o banco de dados.

### 2. Entity Framework
- **Definição**: ORM que automatiza operações CRUD (Create, Read, Update, Delete) e mapeia objetos para tabelas relacionais.
- **Vantagens**:  
  - Reduz a necessidade de código SQL manual.  
  - Facilita a manutenção e extensibilidade.  
  - Suporta abordagens como **Code First** (cria o banco a partir das classes).  

### 3. Acesso sem Entity Framework (ADO.NET)
- **Processo Manual**:  
  - Criação de scripts SQL para tabelas (ex: `ddl-cursos.txt`).  
  - Uso de classes DAO (Data Access Object) para isolamento da lógica de acesso.  
  - Interfaces como `IDbConnection` e classes como `SqlConnection` para conexão com o banco.  
- **Desvantagens**: Código verboso e propenso a erros, com necessidade de gerenciar conexões e transações manualmente.

### 4. Preparação do Ambiente
- Instalação do EF via NuGet:  
  ```powershell
  Install-Package Microsoft.EntityFrameworkCore.SqlServer -Version 1.1
  ```
- Substituição do ADO.NET pelo EF em `Program.cs`, usando `DbContext` e `DbSet<T>` para mapear tabelas.

### 5. Operações CRUD com Entity Framework
- **Create**:  
  ```csharp
  contexto.Cursos.Add(curso);
  contexto.SaveChanges();
  ```
- **Read**:  
  ```csharp
  var cursos = contexto.Cursos.ToList();
  ```
- **Update**:  
  ```csharp
  var curso = contexto.Cursos.First();
  curso.Nome = "Novo Nome";
  contexto.SaveChanges();
  ```
- **Delete**:  
  ```csharp
  var curso = contexto.Cursos.First();
  contexto.Cursos.Remove(curso);
  contexto.SaveChanges();
  ```

### 6. Padrão Repository com Entity
- Criação de `ICursoDAO` para definir contratos.  
- Implementação de `CursoDAOEntity` usando EF, com métodos enxutos:  
  ```csharp
  public class CursoDAOEntity : ICursoDAO {
      private UniversidadeContext _contexto;
      public void Adicionar(Curso curso) {
          _contexto.Cursos.Add(curso);
          _contexto.SaveChanges();
      }
      // Outros métodos CRUD...
  }
  ```

### 7. Relacionamentos entre Tabelas
- **Tipos**:  
  - **1:N** (Um-para-Muitos): Ex: `Categoria` → `Livro`.  
  - **N:N** (Muitos-para-Muitos): Ex: `Aluno` ↔ `Livro` (via tabela `Emprestimo`).  
- **Implementação**:  
  - Propriedades de navegação (ex: `List<Emprestimo>`).  
  - Chaves estrangeiras (ex: `CategoriaID` em `Livro`).  

### 8. Migrações (Migrations)
- Comandos para sincronizar modelo e banco:  
  ```powershell
  Add-Migration NomeDaMigracao
  Update-Database -Verbose
  ```
- **Cuidados**: Resolver conflitos (ex: tabelas existentes) e usar histórico (`__EFMigrationsHistory`).

### 9. Conclusão
- **Entity Framework vs ADO.NET**:  
  - EF oferece produtividade e abstração, enquanto ADO.NET requer controle manual.  
  - EF é ideal para projetos complexos com mudanças frequentes no modelo.  
- **Práticas Recomendadas**:  
  - Usar padrão Repository.  
  - Definir relacionamentos claros nas classes.  
  - Gerenciar migrações para evolução do banco.

### Destaques:
- **Abstração**: O EF elimina a necessidade de escrever SQL manual, mapeando objetos diretamente para tabelas.  
- **Flexibilidade**: Suporte a migrações facilita a evolução do esquema do banco.  
- **Performance**: Métodos como `AddRange` otimizam operações em massa.
