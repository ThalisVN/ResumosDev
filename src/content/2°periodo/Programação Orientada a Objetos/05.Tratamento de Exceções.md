## Tratamento de Exceções

### 1. Introdução
O documento aborda o tratamento de exceções na programação orientada a objetos, com foco em C#. Exceções são notificações de eventos inesperados que interrompem o fluxo normal de um programa. Elas permitem detectar e reagir a erros de forma estruturada, separando a lógica principal do código de tratamento de erros.

### 2. Exceções e Manipulação de Exceções
- **Definição**: Uma exceção sinaliza um erro ou evento inesperado durante a execução do programa.
- **Mecanismo**: O CLR (Common Language Runtime) gerencia o lançamento e captura de exceções, propagando-as até encontrar um manipulador adequado.
- **Vantagens**: Substitui códigos de erro tradicionais, permitindo tratamento centralizado e hierarquias de exceções.

### 3. Fluxo de uma Exceção
- **Exemplo**: Tentativa de ler um arquivo inexistente (`FileNotFoundException`).
- **Pilha de Chamadas**: Quando uma exceção é lançada, o CLR percorre a pilha de chamadas para encontrar um manipulador. Se nenhum for encontrado, o programa é encerrado com uma mensagem de erro.

### 4. Manipulação de Exceções com `try-catch`
- **Estrutura**:
  ```csharp
  try {
      // Código que pode lançar exceções
  } catch (ExceptionType ex) {
      // Tratamento da exceção
  }
  ```
- **Exemplo**: Capturar `FileNotFoundException` e `IOException` ao ler um arquivo.
- **Stack Trace**: Fornece detalhes técnicos sobre o erro, útil para depuração.

### 5. Criando e Lançando Exceções Personalizadas
- **Lançamento**: Usa-se a palavra-chave `throw`.
- **Exceções Personalizadas**: Devem herdar de `System.Exception` ou suas subclasses (`ApplicationException` para exceções de aplicativo).
- **Exemplo**: `SaldoInsuficienteException` para operações bancárias.

### 6. Exceções Geradas pelo Compilador
Lista de exceções comuns:
- `DivideByZeroException`
- `NullReferenceException`
- `OutOfMemoryException`
- `StackOverflowException`

### 7. Bloco `finally` para Limpeza de Recursos
- **Propósito**: Garantir a liberação de recursos (arquivos, conexões) mesmo se ocorrer uma exceção.
- **Exemplo**:
  ```csharp
  TextReader reader = null;
  try {
      reader = new StreamReader(fileName);
      // Operações com o arquivo
  } finally {
      if (reader != null) {
          reader.Close();
      }
  }
  ```
- **Padrão "using"**: Simplifica o gerenciamento de recursos:
  ```csharp
  using (TextReader reader = new StreamReader(fileName)) {
      // Operações com o arquivo
  }
  ```

### 8. Exceções não Compatíveis com CLS
- **Definição**: Exceções que não herdam de `System.Exception`.
- **Captura**: Usando `catch (RuntimeWrappedException ex)` ou um bloco `catch` genérico.

### 9. Conclusão
O uso de exceções em C# é uma prática essencial para:
- Separar a lógica principal do tratamento de erros.
- Evitar código complexo e difícil de manter.
- Fornecer informações detalhadas sobre erros (mensagens, stack trace).
- Gerenciar recursos de forma segura com `finally` ou `using`.
