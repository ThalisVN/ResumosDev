## Banco de dados NoSQL

### 1. **Introdução ao NoSQL**
- **NoSQL (Not Only SQL)**: Classe de bancos de dados **não relacionais**.
- **Objetivo**: Oferecer alternativas para armazenamento e consulta de dados em cenários onde bancos relacionais são limitados (ex: alto volume, escalabilidade, flexibilidade).
- **Características Principais**:
  - Esquemas flexíveis ou inexistentes.
  - Dados semiestruturados ou não estruturados.
  - Alta escalabilidade horizontal.
  - Alta disponibilidade e desemviamento.
  - Consistência eventual (trade-off entre consistência e disponibilidade).
  - Modelos de replicação: mestre-escravo e mestre-mestre.
  - Particionamento horizontal (sharding).
### 2. **Origem e Evolução**
- Surgiu para atender demandas de **aplicações web em grande escala** (ex: Google, Facebook).
- Impulsionado pelo boom das pontocom (final dos anos 1990/início dos anos 2000).
- Popularizado por comunidades de código aberto (ex: MongoDB, Cassandra, Redis).
- Evoluiu para modelos de serviço gerenciado (DBaaS – Database as a Service).

### 3. **Categorias de Bancos NoSQL**

#### a. **Armazenamento Chave-Valor (Key-Value)**
- **Estrutura**: Pares chave-valor (ex: hashmap).
- **Exemplos**: Redis, DynamoDB, Azure Table Storage.
- **Uso ideal**:
  - Sessões de usuário.
  - Preferências e configurações.
  - Cache de alto desempenho.
  - Dados não estruturados.
- **Vantagens**: Simplicidade, escalabilidade, desempenho.

#### b. **Armazenamento Baseado em Documentos (Document Stores)**
- **Estrutura**: Dados armazenados como documentos (ex: JSON, XML).
- **Exemplos**: MongoDB, CouchDB.
- **Uso ideal**:
  - Catálogos de e-commerce.
  - Conteúdo dinâmico (blogs, plataformas de vídeo).
  - Dados semiestruturados com relacionamentos simples.
- **Vantagens**: Flexibilidade, consultas por campos, escalabilidade.

#### c. **Bancos de Dados de Grafos (Graph Databases)**
- **Estrutura**: Nós (entidades) e arestas (relacionamentos).
- **Exemplos**: Neo4j, Amazon Neptune.
- **Uso ideal**:
  - Redes sociais.
  - Detecção de fraudes.
  - Sistemas de recomendação.
  - Análise de conexões complexas.
- **Vantagens**: Consultas relacionais eficientes, suporte a ACID.

#### d. **Bancos Baseados em Colunas (Column-Family)**
- **Estrutura**: Dados armazenados por colunas ou famílias de colunas.
- **Exemplos**: Cassandra, HBase.
- **Uso ideal**:
  - Big Data.
  - Análise de dados em larga escala.
  - Logs e eventos.
- **Vantagens**: Desempenho em leituras massivas, escalabilidade.

### 4. **Características Comuns**
- **Escalabilidade Horizontal**: Adição de nós para expandir capacidade.
- **Disponibilidade**: Replicação de dados para tolerância a falhas.
- **Consistência Eventual**: Dados podem estar temporariamente inconsistentes.
- **Particionamento (Sharding)**: Divisão de dados para distribuir carga.
- **APIs Simples**: Operações básicas de CRUD via API.

### 5. **Comparação com Bancos Relacionais (SQL)**
| Aspecto               | SQL                          | NoSQL                       |
|-----------------------|------------------------------|-----------------------------|
| Esquema               | Fixo                         | Flexível                   |
| Escalabilidade        | Vertical                     | Horizontal                 |
| Consistência          | Forte (ACID)                 | Eventual (BASE)            |
| Modelo de Dados       | Tabelas                      | Documentos, Grafos, etc.   |
| Consultas             | SQL (poderoso)               | APIs simples               |
| Transações            | Suporte completo             | Limitado (exceto grafos)   |

### 6. **Conclusão**
- NoSQL é ideal para:
  - Aplicações modernas com alto volume de dados.
  - Cenários que exigem escalabilidade e flexibilidade.
  - Dados semiestruturados ou não estruturados.
- Cada categoria atende a necessidades específicas:
  - **Chave-valor**: Simplicidade e desempenho.
  - **Documentos**: Flexibilidade e consultas por campo.
  - **Grafos**: Relacionamentos complexos.
  - **Colunas**: Análise de grandes volumes.
