## Sistemas Gerenciadores de Bancos de Dados (SGBD)

### **1. Introdução**

- **SGBD**: Conjunto de programas que gerenciam bancos de dados (BD), permitindo definição, manipulação, compartilhamento e segurança dos dados.
    
- **Evolução das Arquiteturas**:
    
    - **Mainframes**: Sistemas centralizados em computadores de grande porte.
        
    - **Cliente-Servidor**: Modularização com servidores dedicados.
        
    - **Distribuídos**: Dados e processamento distribuídos em redes.
        
- **Histórico**:
    
    - Década de 1960: Surgimento dos primeiros SGBDs (IDS e IMS), baseados em modelos **hierárquico** e **em rede**.
        
    - Década de 1970: Modelo **relacional** (Codd) e linguagem **SQL** (padronizada nos anos 1980).
        
    - Década de 2000: Modelos **NoSQL** para dados semiestruturados (JSON, XML) e **bancos de dados em nuvem**.
        

### **2. Características dos SGBDs**

- **Abstração de Dados**: Oculta detalhes de armazenamento, permitindo interação simplificada.
    
    - **Modelos de Dados**:
        
        - **Conceitual**: Representação fiel do ambiente (ex: diagrama entidade-relacionamento).
            
        - **Lógico**: Adaptado a tecnologias (ex: tabelas relacionais).
            
        - **Físico**: Detalhes de armazenamento (arquivos, índices).
            
- **Arquitetura de Três Esquemas**:
    
    - **Nível Interno (físico)**: Armazenamento em disco.
        
    - **Nível Conceitual (lógico)**: Estrutura global do BD.
        
    - **Nível Externo (visões)**: Dados personalizados para usuários.
        
- **Propriedades ACID**:
    
    - **Atomicidade**: Transações completas ou canceladas.
        
    - **Consistência**: Dados válidos após transações.
        
    - **Isolamento**: Transações concorrentes não interferem.
        
    - **Durabilidade**: Alterações persistem após falhas.
        

### **3. Linguagens de Acesso**

- **DDL (Data Definition Language)**: Define esquemas (ex: `CREATE TABLE`).
    
- **DML (Data Manipulation Language)**: Manipula dados (ex: `SELECT`, `INSERT`).
    
- **SQL**: Padrão que combina DDL, DML, DCL (controle de acesso) e DTL (transações).
    

### **4. Componentes e Arquiteturas**

- **Componentes Principais**:
    
    - **Gerenciador de Armazenamento**: Controla acesso físico aos dados.
        
    - **Processador de Consultas**: Otimiza e executa consultas.
        
    - **Gerenciador de Transações**: Garante ACID.
        
- **Arquiteturas**:
    
    - **Centralizada**: Mainframes com terminais "burros".
        
    - **Cliente-Servidor**:
        
        - **2 Camadas**: Cliente + Servidor de BD.
            
        - **3 Camadas**: Cliente + Servidor de Aplicação + Servidor de BD (mais segura).
            
    - **Distribuída**: Dados fragmentados em múltiplos servidores.
        

### **5. Classificação dos SGBDs**

- **Por Modelo de Dados**:
    
    - **Relacional**: Tabelas com SQL (mais comum).
        
    - **Orientado a Objetos (BDOO)**: Para dados complexos.
        
    - **NoSQL**: Documentos (JSON), chave-valor, grafos, colunas.
        
- **Por Acesso**:
    
    - **Monousuário** vs. **Multiusuário**.
        
    - **Centralizado** vs. **Distribuído** (homogêneo/heterogêneo).
        

### **6. Conclusão**

- SGBDs evoluíram para atender demandas de volume, complexidade e acessibilidade.
    
- Principais vantagens: **abstração**, **segurança**, **concorrência**, **recuperação de falhas**.
    
- Arquiteturas modernas (cliente-servidor, distribuída) suportam aplicações web e big data.
    

---

**Destaques**:

- A **SQL** é a linguagem dominante para SGBDs relacionais.
    
- Modelos **NoSQL** atendem a necessidades de flexibilidade e escalabilidade.
    
- Propriedades **ACID** são críticas para integridade dos dados.
