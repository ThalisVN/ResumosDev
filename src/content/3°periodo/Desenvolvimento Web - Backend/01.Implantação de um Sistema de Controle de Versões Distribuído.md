# Implantação de um Sistema de Controle de Versões Distribuído

## Introdução
Com a crescente complexidade dos sistemas e a necessidade de colaboração entre desenvolvedores, surge a necessidade de controlar versões de arquivos em ambientes locais e remotos.

## Git
- **Criador**: Linus Torvalds.  
- **O que é**: Sistema de controle de versão distribuído, atuando no ambiente local.  
- **Funcionamento**: Baseia-se em uma estrutura de árvore com ramificações (*branches*), facilitando a gestão colaborativa de alterações.  
- **Instalação**: Simples e disponível para Windows, Linux/Unix e Mac.  
- **Criação de repositório local**: Pode ser feito via interface gráfica (Git GUI) ou linha de comando.  
- **Configuração inicial**: É necessário definir nome de usuário e e-mail para uso futuro com o GitHub.

## GitHub
- **O que é**: Serviço de hospedagem de código-fonte baseado em Git, funcionando como repositório remoto.  
- **Funcionalidade**: Permite sincronização com repositórios locais, facilitando o compartilhamento e o controle de versão em equipe.  
- **Criação de conta**: Exige usuário único, e-mail válido e senha com 8–15 caracteres.  
- **Criação de repositório remoto**: Após login, é possível criar um repositório público ou privado.

## Relacionamento entre Repositórios Local e Remoto
- Após criar os repositórios, é possível associá-los através do Git GUI (menu *Remote* → *Add*).  
- A associação permite sincronizar arquivos entre local e remoto.

## Transferência do Repositório Local para o GitHub
1. **Preparar arquivos**: Movê-los para a área *Staged* no Git GUI.  
2. **Commit**: Adicionar uma mensagem descritiva e confirmar as alterações.  
3. **Push**: Enviar os arquivos para o repositório remoto no GitHub.  
4. **Verificação**: Confirmar no GitHub que os arquivos foram transferidos com sucesso.

## Comandos Básicos do Git

### 1. **Criando um repositório**
```bash
git init
```
- Cria um repositório Git local, gerando uma pasta oculta `.git`.

### 2. **Comando `add`**
- Adiciona arquivos ao monitoramento do Git.
- Exemplos:
  ```bash
  git add arquivo.c
  git add *.c
  git add .
  ```

### 3. **Comando `status`**
```bash
git status
```
- Mostra o estado dos arquivos no repositório (modificados, adicionados, etc.).

### 4. **Comando `commit`**
```bash
git commit -m "Mensagem do commit"
```
- Cria uma versão (snapshot) dos arquivos adicionados.
- A opção `-a` permite pular o `add` antes do commit.

### 5. **Comando `log`**
```bash
git log
```
- Exibe o histórico de commits.
- A opção `-p` mostra as diferenças entre versões.

## Transferência do Repositório Remoto para o Local

### Clonagem (`clone`)
```bash
git clone <URL-do-repositório>
```
- Copia todo o repositório remoto (arquivos, histórico e branches) para o local.
- Exemplo: `git clone https://github.com/usuario/repositorio.git`

### Diferença entre `clone` e `download ZIP`
- `clone` traz todo o histórico de versões.
- `download ZIP` traz apenas os arquivos da última versão.

## Atualização do Repositório Local

### Comando `remote`
```bash
git remote -v
```
- Lista os repositórios remotos vinculados.
- Para adicionar um novo remoto:
  ```bash
  git remote add <nome> <URL>
  ```

### Comando `fetch`
```bash
git fetch <nome-do-remoto>
```
- Busca atualizações do remoto, mas **não faz merge** automaticamente.

### Comando `pull`
```bash
git pull <nome-do-remoto>
```
- Busca atualizações e **faz merge automático** com o repositório local.
- Geralmente usado após `git fetch` ou diretamente para sincronizar.

## Pontos Importantes
- O Git permite trabalho distribuído: cada desenvolvedor tem uma cópia completa do projeto.
- O GitHub oferece hospedagem remota e colaboração.
- Comandos como `add`, `commit`, `push` (visto no capítulo anterior) e `pull` são essenciais para o fluxo de trabalho.
