# Construção do modelo MVC de um cenário real

## Introdução
O capítulo aborda a aplicação do padrão arquitetural **Model-View-Controller (MVC)** em um cenário real, explicando sua importância para a organização, reutilização e manutenção de sistemas de informação.

## Contexto: Arquitetura de Software
- A arquitetura de software organiza os componentes do sistema e suas interações.
- Deve atender a requisitos funcionais e não funcionais, além de ser flexível.
- Arquiteturas bem projetadas facilitam a comunicação, tomada de decisão e reutilização.

## O Modelo MVC
- É um padrão arquitetural de **três camadas**:
  1. **Model (Modelo)**: Lógica de negócio e regras do sistema.
  2. **View (Visão)**: Interface com o usuário (ex.: páginas web).
  3. **Controller (Controlador)**: Intermediário que processa entradas da View e atualiza o Model.
- Promove **separação de responsabilidades**, baixo acoplamento e alta coesão.
- Facilita a manutenção e evolução do sistema.

## Exemplo Prático: Sistema Escolar
Cenário: sistema para **diário de classe** e **lançamento de notas**.

### Camadas no Contexto Escolar:
- **View**: Telas de cadastro de alunos, lançamento de notas, consulta de frequência.
- **Controller**: Valida dados (ex.: idade com 4 dígitos, números no nome), direciona ações.
- **Model**: Contém regras de negócio (ex.: cálculo de média, verificação de frequência) e acesso ao banco de dados.

### Banco de Dados Exemplo:
- **TB_Cadastro**: Alunos (ID, Nome).
- **TB_Notas**: Notas dos alunos.
- **TB_FDC**: Frequência em sala.
- **TB_Resultado**: Resultado final (aprovado/reprovado) com base em notas e faltas.

### Exemplo de Dados:
```
TB_Cadastro: Pedro, João, Maria, Caio, Katharine, Amanda, Fernanda
TB_Notas: Pedro (10), João (7), Maria (5), Caio (9), Katharine (8), Amanda (9), Fernanda (4)
TB_FDC: Percentual de presença de cada aluno.
TB_Resultado: Aprovado/Reprovado conforme média (>=5) e frequência (>50%).
```

## Arquitetura em Camadas e Evolução
- Sistemas antigos de **uma camada** não suportavam muitos usuários.
- **Arquitetura cliente-servidor** (duas camadas) separa servidores (serviços) e clientes (consumidores).
- O MVC pode ser combinado com outras arquiteturas para sistemas complexos (ex.: múltiplas Views, integração com mobile, bancos de dados distribuídos).

## Conclusão
- O MVC é amplamente utilizado no desenvolvimento web moderno.
- Permite a separação clara entre interface, controle e lógica de negócio.
- Facilita a organização do código, manutenção e escalabilidade.
- O exemplo do sistema escolar ilustra como as três camadas interagem em um cenário real.
