# Análise e Modelagem de Requisitos para um Fórum de Discussão Online

---

## 1. Conceito de Cenário Real e Levantamento de Requisitos
- **Cenário real:** Conjunto de fatos ou situações relacionadas a um problema do mundo real, a ser resolvido com tecnologia da informação.
- **Requisitos de software:** Condições ou capacidades que o sistema deve atender para satisfazer as necessidades do cliente.
- **Levantamento de requisitos:** Etapa fundamental para garantir visão comum entre usuários e desenvolvedores, utilizando técnicas como reuniões, entrevistas e observações.

---

## 2. Cenário Real: Fórum de Discussão da Treina-sis
- **Empresa:** Treina-sis (fornece treinamentos online em desenvolvimento de sistemas).
- **Objetivo:** Criar um fórum para integrar instrutores e usuários, além de divulgar a marca e atrair novos clientes.
- **Termos-chave:**
  - **Fórum:** plataforma online com usuários, temas e comentários.
  - **Usuário:** pessoa cadastrada (pode ou não ser aluno).
  - **Tema:** questão publicada para discussão.
  - **Comentário:** resposta a um tema.

---

## 3. Diagramas de Modelagem do Sistema

### Diagrama de Casos de Uso (Figura 1)
Representa as funcionalidades do sistema do ponto de vista do usuário:
- Realizar cadastro
- Fazer login
- Pesquisar tema
- Criar tema
- Ler comentários

### Diagrama de Atividades (Figura 2)
Especifica o fluxo de processos:
1. Login ou cadastro (primeiro acesso)
2. Pesquisa de conteúdo
3. Decisão: criar novo tema ou acessar tema existente
4. Ler ou postar comentários

### Diagrama de Classes (Figura 3)
Modela a estrutura do sistema com três classes principais:

| Classe       | Atributos (privados)                         | Métodos (públicos)                    |
|--------------|----------------------------------------------|---------------------------------------|
| **Usuário**  | login, nome, email, senha                    | cadastrar(), login(), criarTema()     |
| **Tema**     | id, descrição, momento, usuário              | criar(), lerComentarios()             |
| **Comentário**| id, descrição, momento, usuário, tema        | escrever(), ler()                     |

**Relacionamentos (composição):**
- **Tema × Comentário:** 1 tema tem 0..* comentários
- **Comentário × Usuário:** 1 comentário tem 1 autor
- **Tema × Usuário:** 1 tema tem 1 criador

## 4. Necessidades do Sistema (N-1 a N-6)

| Código | Necessidade                | Descrição                                                                 |
|--------|----------------------------|---------------------------------------------------------------------------|
| **N-1**| Realizar cadastro          | Usuário deve poder se cadastrar para acessar o conteúdo                   |
| **N-2**| Fazer login                | Autenticação para acessar temas e comentários                             |
| **N-3**| Pesquisar tema             | Busca por palavras-chave nos temas existentes                             |
| **N-4**| Criar tema                 | Usuários cadastrados podem criar novos temas                              |
| **N-5**| Ler comentários            | Navegar entre respostas com informações de data, hora e autor             |
| **N-6**| Escrever comentário        | Responder a temas com comentários em ordem cronológica                    |

## 5. Requisitos Funcionais Especificados (RF-1 a RF-6)

### RF-1: Realizar cadastro
- **Descrição:** Interface para cadastro de usuário
- **Prioridade:** Alta
- **Propósito:** Registrar login, nome, email e senha
- **Validação:** Confirmação por email

### RF-2: Fazer login
- **Descrição:** Interface para autenticação
- **Prioridade:** Alta
- **Propósito:** Validar login e senha
- **Recurso:** Recuperação de senha

### RF-3: Pesquisar tema
- **Descrição:** Interface de busca
- **Prioridade:** Média
- **Propósito:** Localizar temas por palavras-chave

### RF-4: Criar tema
- **Descrição:** Interface para criação de temas
- **Prioridade:** Alta
- **Propósito:** Inserir novo tema com descrição, momento e usuário
- **Observação:** ID único sequencial automático

### RF-5: Ler comentários
- **Descrição:** Interface para leitura de comentários
- **Prioridade:** Alta
- **Propósito:** Apresentar comentários com descrição, data/hora e autor
- **Ordenação:** Cronológica (mais antigos primeiro)

### RF-6: Escrever comentário
- **Descrição:** Interface para escrever comentários
- **Prioridade:** Alta
- **Propósito:** Registrar comentário com descrição, momento, usuário e tema
- **Observação:** ID único sequencial automático

## 6. Princípios de Orientação a Objetos Aplicados
- **Encapsulamento:** Atributos privados (`-`) e métodos públicos (`+`)
- **Composição:** Relacionamentos fortes onde objetos dependem da existência de outros
- **Abstração:** Classes representam entidades do mundo real

---

## 7. Conclusão
- A **análise e modelagem de requisitos** é essencial para o planejamento de sistemas antes da implementação.
- O **cenário do fórum de discussão** ilustra como transformar necessidades do cliente em requisitos funcionais específicos.
- **Diagramas UML** (casos de uso, atividades e classes) são ferramentas fundamentais para documentar e comunicar o design do sistema.
- A **especificação detalhada de requisitos** serve como base para o desenvolvimento e garante que o produto final atenda às expectativas do cliente.
