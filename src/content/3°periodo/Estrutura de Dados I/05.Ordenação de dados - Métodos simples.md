# Ordenação de dados - Métodos simples

## **1. Bubblesort (Ordenação Bolha)**
- **Funcionamento**: Compara cada elemento com os subsequentes, trocando-os se estiverem fora de ordem. A cada iteração, o menor elemento “sobe” para a posição correta, como bolhas em água.
- **Características**:
  - Fácil de entender e implementar.
  - Ineficiente para grandes volumes de dados (muitas comparações e trocas).
  - Complexidade: **O(n²)** no pior caso.
- **Exemplo**: Vetor `{3, 5, 2, 1, 4}` ordenado em várias iterações com múltiplas trocas.

---

## **2. Selectionsort (Ordenação por Seleção)**
- **Funcionamento**: Em cada iteração, encontra o menor elemento restante e o coloca na posição correta, realizando **apenas uma troca por fase**.
- **Características**:
  - Realiza menos trocas que o Bubblesort.
  - Ainda ineficiente para grandes vetores.
  - Complexidade: **O(n)**.
- **Exemplo**: Mesmo vetor `{3, 5, 2, 1, 4}` ordenado selecionando o menor elemento a cada fase.

---

## **3. Insertionsort (Ordenação por Inserção)**
- **Funcionamento**: Percorre o vetor da segunda posição em diante, inserindo cada elemento na posição correta entre os já ordenados, deslocando os demais se necessário.
- **Características**:
  - Eficiente para vetores **pré-ordenados ou pequenos**.
  - Poucas comparações e trocas em dados parcialmente ordenados.
  - Complexidade: **O(n²)** no pior caso, **O(n)** no melhor.
- **Exemplo**: Vetor `{3, 5, 2, 1, 4}` ordenado inserindo cada elemento na posição adequada.

---

## **4. Comparação Geral**
| Método            | Vantagens                      | Desvantagens                   | Melhor Caso |
| ----------------- | ------------------------------ | ------------------------------ | ----------- |
| **Bubblesort**    | Simples, didático              | Muito lento, muitas trocas     | O(n²)       |
| **Selectionsort** | Poucas trocas                  | Ineficiente, comparações fixas | O(n)        |
| **Insertionsort** | Bom para dados quase ordenados | Lento para dados desordenados  | O(n)        |

---

## **5. Conclusão**
- Esses métodos são **básicos e educativos**, ideais para compreender os fundamentos da ordenação.
- Não são recomendados para **grandes conjuntos de dados** na prática, onde algoritmos como **QuickSort** ou **MergeSort** são mais eficientes.
- A escolha do método depende do **tamanho dos dados**, do **estado inicial** (ordenado ou não) e do **custo de trocas vs. comparações**.
