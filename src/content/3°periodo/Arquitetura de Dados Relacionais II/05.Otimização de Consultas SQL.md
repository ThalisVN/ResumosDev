# Otimização de Consultas SQL
## 1. Introdução à Otimização de Consultas
- **Problema**: Com o tempo, bancos de dados acumulam fragmentos e consultas podem se tornar lentas
- **Solução**: Intervenção do DBA (Database Administrator) para identificar gargalos e otimizar consultas
- **Abordagem**: Remover fragmentos, avaliar estatísticas, criar índices apropriados

## 2. Análise de Custos em Consultas SQL

### Analogia com Transporte de Cargas
- Distância maior = custo maior
- Carga maior = mais viagens necessárias
- Planejamento de rota = otimizador de consultas

### Três Etapas do Processamento de uma Consulta

| Etapa | Funcionalidade |
|-------|----------------|
| **Parse** (análise e tradução) | Traduz SQL para formato interno; verifica sintaxe e existência de objetos |
| **Optimization** (otimização) | Investiga estratégias de acesso; seleciona índices; define ordem de JOINs |
| **Execution** (execução/avaliação) | Executa o plano; envolve custos de disco, CPU e comunicação |

### Custo da Consulta no MySQL
- Soma de: **Read** (leitura) + **Evaluation** (avaliação)
- Exemplo: custo 2.21 = 1.01 (Read) + 1.20 (Evaluation)

### Tabelas de Custo no MySQL
- `mysql.server_cost` – custos gerais do servidor
- `mysql.engine_cost` – custos específicos do motor de armazenamento

## 3. Fragmentação de Índices

### Causas da Fragmentação
- Inserções, atualizações e deleções frequentes
- Registros deletados "fisicamente" deixam espaços vazios

### Tipos de Fragmentação
- **Física**: espaços vazios entre registros no armazenamento
- **Lógica**: armazenamento não segue ordenação lógica da tabela

### Identificando Fragmentação no MySQL
```sql
SELECT table_name, 
       table_rows AS "Registros",
       ROUND(data_length/(1024*1024),2) AS "Dados (MB)",
       ROUND(index_length/(1024*1024),2) AS "Índices (MB)",
       ROUND(data_free/(1024*1024),2) AS "Livre (MB)",
       ROUND(data_free/data_length,2) AS "LivrePct"
FROM information_schema.TABLES
WHERE table_schema = "employees";
```

### Comandos para Tratar Fragmentação

| Comando | Funcionalidade |
|---------|----------------|
| `OPTIMIZE TABLE nome` | Reorganiza armazenamento físico; reduz espaços vazios |
| `ANALYZE TABLE nome` | Atualiza estatísticas de distribuição de chaves |

### Regra prática
- **Fragmentação > 20%** → executar rotina de `OPTIMIZE TABLE`

## 4. Análise de Gargalos em Consultas SQL

### SQL é Declarativa (não procedural)
- Usuário especifica **o que** quer, não **como** obter
- Otimizador escolhe a estratégia (navegação automática)

### Problemas Comuns
1. **Estatísticas desatualizadas** – otimizador toma decisões ruins
2. **Ausência de índices apropriados** – leitura total da tabela (full table scan)

### Cenário 1: Consulta sem índice apropriado
```sql
SELECT * FROM salaries WHERE to_date = '9999-01-01';
```
- **Antes**: Full table scan (custo alto, lê todos registros)
- **Depois**: Criar índice → `CREATE INDEX idx_to_date ON salaries(to_date);`
- **Resultado**: Non-unique key lookup (leitura apenas dos registros relevantes)

### Cenário 2: JOIN sem índice apropriado
```sql
SELECT e.emp_no, e.first_name, e.last_name, t.title
FROM employees e
INNER JOIN titles t ON t.emp_no = e.emp_no
WHERE t.to_date = '9999-01-01';
```
- **Otimização**: Criar índice composto → `CREATE INDEX idx_titles_atual ON titles(to_date, emp_no);`

## 5. Visões Indexadas (Indexed Views / Materialized Views)

### Definição
- View cujo conteúdo é **calculado e armazenado** (dados redundantes)
- Muito menos dispendioso ler o conteúdo armazenado do que executar a consulta original

### Disponibilidade por SGBD

| SGBD | Suporte | Nome |
|------|---------|------|
| **MySQL** | ❌ Não suporta | – |
| **SQL Server** | ✅ Suporta | Indexed View |
| **Oracle** | ✅ Suporta | Materialized View |

### Exemplo (Oracle)
```sql
CREATE MATERIALIZED VIEW nome_view
TABLESPACE tablespace
BUILD IMMEDIATE
REFRESH COMPLETE
ENABLE QUERY REWRITE
AS SELECT ... FROM ... GROUP BY ...;
```

### Exemplo (SQL Server)
```sql
CREATE VIEW Sales.vOrders WITH SCHEMABINDING AS SELECT ...
GO
CREATE UNIQUE CLUSTERED INDEX IDX_V1 ON Sales.vOrders (OrderDate, ProductID);
```

## 6. Otimização de Agrupamento e Funções de Agregação

### Covering Index (Índice Cobridor)
- Índice que contém **todas as colunas** necessárias para a consulta
- Beneficia operações de `GROUP BY` e funções agregadas (`SUM`, `AVG`, `COUNT`)

### Exemplo
```sql
-- Consulta lenta (full table scan)
SELECT to_date, SUM(salary) FROM salaries GROUP BY to_date;

-- Criar índice cobridor
CREATE INDEX idx_to_date_salary ON salaries (to_date, salary);

-- Resultado: Index range scan (muito mais rápido)
```

### Benefício
- Elimina a necessidade de acessar a tabela original
- Toda a consulta é atendida **apenas pelo índice**

## 7. Resumo de Comandos para Otimização

| Comando | Finalidade |
|---------|------------|
| `OPTIMIZE TABLE` | Reorganizar armazenamento físico (remove fragmentação) |
| `ANALYZE TABLE` | Atualizar estatísticas de distribuição de chaves |
| `CREATE INDEX` | Criar índice para acelerar consultas |
| `INFORMATION_SCHEMA.STATISTICS` | Consultar estatísticas e cardinalidade dos índices |

## 8. Conclusão

### Principais Causas de Gargalo
- Ausência de índices apropriados
- Estatísticas desatualizadas
- Fragmentação de dados e índices
- Consultas mal escritas que impedem uso de índices

### Estratégias de Otimização

| Estratégia | Quando aplicar |
|------------|----------------|
| Criar índices em colunas de WHERE, JOIN, GROUP BY | Consultas frequentes com filtros |
| Atualizar estatísticas (`ANALYZE TABLE`) | Dados sofreram muitas alterações |
| Remover fragmentação (`OPTIMIZE TABLE`) | Espaço livre > 20% da tabela |
| Usar covering index | Consultas com GROUP BY + agregações |
| Considerar visões materializadas | Consultas complexas e frequentes (Oracle/SQL Server) |

### Pontos-Chave para o DBA
1. **Otimizador** decide o plano de execução baseado em estatísticas
2. **Estatísticas desatualizadas** levam a planos ruins
3. **Índices adequados** transformam `full table scan` em `key lookup`
4. **Covering index** pode atender consultas inteiras sem acessar a tabela
5. **Fragmentação** impacta desempenho – monitorar e otimizar periodicamente
