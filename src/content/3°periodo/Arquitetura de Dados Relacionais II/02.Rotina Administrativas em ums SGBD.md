# Rotina Administrativas em um SGBD

## 1. Introdução à Administração de SGBD
- **Contexto**: Empresas dependem de bancos de dados para armazenar informações críticas
- **Desafios**: Ransomware, falhas de hardware/software, corrupção de dados
- **Profissional-chave**: DBA (Database Administrator) – responsável pela recuperação e continuidade do negócio

## 2. Backup e Restauração – Conceitos e Políticas

### Plano de Recuperação de Desastre (DRP)
- Documento formal com instruções para responder a incidentes não planejados
- Inclui estratégias para minimizar efeitos e retomar operações

### Indicadores Críticos

| Indicador | Significado | Pergunta-chave |
|-----------|-------------|----------------|
| **RPO** (Recovery Point Objective) | Quanto de informação pode ser perdida | Perder 23 horas de dados é aceitável? |
| **RTO** (Recovery Time Objective) | Tempo para retomar operações | Aguardar 4 horas de restauração é viável? |

### Perguntas para a Política de Backup
- Qual a frequência dos backups? (impacta o RPO)
- Quais dados realmente precisam de backup?
- Por quanto tempo reter os backups? (Legislação: 5 anos – Código Tributário Nacional)
- Como minimizar o tamanho do backup? (compactação)
- Testar restaurações periodicamente?

## 3. Construção de Jobs (Rotinas Automatizadas)

### Processo de Automação
1. **Script** – comandos de exportação (ex: mysqldump)
2. **Agendamento** – executar sem intervenção humana
3. **Armazenamento** – local íntegro e seguro

### Ferramentas de Agendamento
- **Windows**: Task Scheduler (Agendador de Tarefas)
- **Linux**: Crontab

### Passos no Windows Task Scheduler
1. Criar pasta (ex: "Backups")
2. Criar tarefa básica com nome sugestivo (ex: BKP_MYSQL_COMPLETO_SEMANAL)
3. Definir disparador (diário, semanal, mensal + horário)
4. Configurar ação: "Iniciar um programa" → apontar script de backup

## 4. Implementação de Rotinas de Importação/Exportação

### Dump (Backup Lógico) vs Backup Físico

| Tipo | Descrição | Vantagens | Desvantagens |
|------|-----------|-----------|---------------|
| **Dump** | Arquivo com instruções SQL (INSERT, CREATE) | Fácil transporte entre servidores | Pode ser lento em grandes bases |
| **Backup físico** | Cópia completa + mudanças incrementais | Inclui usuários, permissões | Mais complexo |

### Comandos mysqldump (MySQL)

| Comando | Funcionalidade |
|---------|----------------|
| `mysqldump -u user -p banco > arquivo.sql` | Exportar banco completo |
| `--lock-tables` | Bloquear tabelas durante dump (consistência) |
| `--routines` | Incluir procedures e functions |
| `--ignore-table` | Ignorar tabelas específicas |
| `--no-data` | Exportar apenas estrutura (schema) |
| `mysqldump banco tabela` | Exportar tabela específica |

### Importação de Dump
```sql
CREATE DATABASE novo_banco;
mysql -u user -p novo_banco < arquivo.sql
```

## 5. Gestão de Metadados (INFORMATION_SCHEMA)

**Metadado**: Dado que fala sobre os dados. Todo SGBD padrão SQL-92 possui o schema `INFORMATION_SCHEMA`.

### Consultas Úteis

| Objetivo | Consulta/Comando |
|----------|------------------|
| Listar bancos | `SELECT * FROM information_schema.schemata` |
| Qtde de registros | `SELECT table_name, table_rows FROM information_schema.tables WHERE table_schema = 'db'` |
| Tamanho do banco | `SUM(data_length + index_length)` em MB |
| Espaço livre | `SUM(data_free)` em MB |

## 6. Comandos SQL para Monitoramento

### Disponibilidade do Servidor
```sql
-- Tempo ligado (uptime)
SELECT VARIABLE_VALUE FROM performance_schema.session_status 
WHERE VARIABLE_NAME = 'Uptime';
```

### Monitoramento de Conexões

| Variável | Significado |
|----------|-------------|
| `Threads_connected` | Conexões atuais |
| `Max_used_connections` | Pico de conexões desde inicialização |
| `Max_connections` | Limite máximo permitido |
| `Aborted_connects` | Tentativas falhas (possível ataque) |

**Alerta**: Se `max_used_connections / max_connections > 85%`, aumentar limite.

### Queries Lentas
```sql
SELECT * FROM information_schema.processlist 
WHERE command <> 'Sleep' 
ORDER BY time DESC;
```

## 7. Controle de Recuperação e Falhas

### Tipos de Falhas
- **Armazenamento**: discos corrompidos
- **Sistêmica**: hardware, energia, bugs
- **Transação**: lógica (espaço insuficiente) ou sistema (bloqueio)

### Técnicas de Recuperação

| Técnica | Funcionamento | Operações |
|---------|---------------|-----------|
| **Modificação adiada** | Escrita no disco só após confirmação | NO-UNDO / REDO |
| **Modificação imediata** | Escrita pode ocorrer antes da confirmação | UNDO / REDO |

### Log e Checkpoint
- **Log**: sequência de registros de todas as atualizações
- **Checkpoint**: ponto onde transações confirmadas são forçadas do buffer para o disco
- Em caso de falha, UNDO e REDO são avaliados a partir do último checkpoint

### Garantia das Propriedades ACID
- Atomicidade, Consistência, Isolamento, Durabilidade
- Implementadas via log de transação e gerenciamento de buffer

## 8. Conclusão
O administrador de banco de dados deve:
- Implementar políticas de backup com RPO/RTO definidos
- Automatizar rotinas via scripts e agendadores
- Monitorar metadados (tamanho, crescimento, conexões, queries lentas)
- Compreender mecanismos de recuperação via log e checkpoint
- Garantir a integridade dos dados mesmo em cenários de falha
