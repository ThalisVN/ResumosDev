# Programação avançada em SQL

## 1. Introdução à Programação Avançada em SQL
- **Objetivo**: Incorporar regras de negócio diretamente no banco de dados
- **Recursos disponíveis**: Restrições (constraints), funções (functions), stored procedures, views e triggers
- **Benefícios**: Integridade dos dados, segurança, reutilização de código, manutenção centralizada
- **SGBD de referência**: MySQL (com conceitos aplicáveis a Oracle, SQL Server, IBM)

## 2. Implementação de Restrições em Tabelas e Colunas

### Tipos de Restrições de Integridade

| Restrição | Funcionalidade |
|-----------|----------------|
| **NOT NULL** | Coluna deve ter valor válido (não pode ser vazia) |
| **UNIQUE** | Impede valores duplicados na coluna |
| **CHECK** | Limita valores aceitos (ex: BETWEEN 1 AND 100) |

### Exemplo prático (tabela DEPARTMENTS)
```sql
dept_name VARCHAR(255) NOT NULL UNIQUE,
dept_max_employees INT NOT NULL CHECK (dept_max_employees BETWEEN 1 AND 100)
```

## 3. Construção de Views (Visões)

**Definição**: Tabela virtual derivada de uma ou mais tabelas básicas. Não há arquivo armazenado diretamente – apenas a definição fica no dicionário.

### Utilidades das Views
- Focalizar, simplificar e personalizar a percepção dos dados
- Mecanismo de segurança (acesso sem permissão direta às tabelas)
- Compatibilidade com versões anteriores

### Comandos para Views

| Comando | Funcionalidade |
|---------|----------------|
| `CREATE VIEW nome AS SELECT ...` | Criar visão |
| `ALTER VIEW nome AS SELECT ...` | Alterar definição (preserva permissões) |
| `DROP VIEW nome` | Excluir visão |

### Benefício
Abstrai a complexidade de junções (JOINs) para usuários finais e desenvolvedores

## 4. Construção de Triggers (Gatilhos)

**Definição**: Objetos vinculados a tabelas, acionados automaticamente em operações INSERT, UPDATE ou DELETE.

### Contextos no MySQL

| Operação | NEW | OLD |
|----------|-----|-----|
| INSERT | Valores inseridos | Nenhum |
| UPDATE | Novos valores | Valores anteriores |
| DELETE | Nenhum | Valores anteriores |

### Exemplo de uso
- Auditoria de alterações salariais
- Capturar usuário, data/hora, valores antes/depois

### Comandos para Triggers

| Comando | Funcionalidade |
|---------|----------------|
| `CREATE TRIGGER nome AFTER INSERT ON tabela FOR EACH ROW ...` | Criar gatilho |
| `DROP TRIGGER nome` | Excluir (MySQL não suporta ALTER TRIGGER) |

### Observação
- **MySQL**: não suporta ALTER TRIGGER (deve recriar)
- **SQL Server**: suporta ALTER TRIGGER

## 5. Modularização com Funções (Functions)

**Definição**: Objetos que aceitam parâmetros, executam cálculos e retornam um valor (escalar ou tabela).

### Classificação

| Tipo | Comportamento | Exemplo |
|------|---------------|---------|
| **Determinística** | Mesmo resultado com mesmos parâmetros | Média salarial |
| **Não determinística** | Resultado varia mesmo sem alteração nos dados | NOW(), CURRENT_DATE |

### Comandos para Functions

| Comando | Funcionalidade |
|---------|----------------|
| `CREATE FUNCTION nome (params) RETURNS tipo DETERMINISTIC/NOT DETERMINISTIC RETURN ...` | Criar função |
| `DROP FUNCTION nome` | Excluir (MySQL não suporta ALTER FUNCTION) |

### Exemplos
- `fnc_ultimosalario_funcionario` – retorna último salário (determinística)
- `fnc_calcular_idade` – calcula idade com base em data de nascimento (não determinística)

## 6. Modularização com Procedimentos Armazenados (Stored Procedures)

**Definição**: Encapsulam tarefas repetitivas com suporte a múltiplas instruções, variáveis, execuções condicionais e manipulação de dados.

### Vantagens
- Redução de idas e vindas entre aplicação e banco
- Ganho de desempenho (uma requisição processa várias regras)
- Manutenção centralizada (altera no banco, todas aplicações usam nova versão)

### Comandos para Procedures

| Comando | Funcionalidade |
|---------|----------------|
| `CREATE PROCEDURE nome (params) BEGIN ... END` | Criar procedure |
| `DROP PROCEDURE nome` | Excluir (MySQL não suporta ALTER) |
| `CALL nome(params)` | Executar procedure (MySQL) |

### Estrutura de uma Procedure
- Declaração de variáveis (`DECLARE`)
- Instruções SQL (INSERT, UPDATE, DELETE)
- Controle de fluxo
- Possibilidade de retornar dados via SELECT

### Exemplo de uso
Reajuste salarial por departamento: aplica aumento, encerra registro anterior, insere novo salário

## 7. Comando MERGE (Integração de Dados)

**Definição**: Executa operações de inserção, atualização ou exclusão em uma tabela de destino com base nos resultados de uma união com uma tabela de origem.

### Sintaxe básica
```sql
MERGE Destino AS D
USING Origem AS O ON (D.chave = O.chave)
WHEN MATCHED THEN UPDATE SET ...
WHEN NOT MATCHED THEN INSERT ...
```

### Observação
- **MySQL**: não suporta MERGE nativamente
- **SQL Server**: suporta (exemplo do documento)

## 8. ETL (Extração, Transformação e Carga de Dados)

**Definição**: Processo fundamental em Business Intelligence e Data Warehouse.

### Significado
| Etapa | Descrição |
|-------|-----------|
| **Extract** | Buscar dados de diversas fontes distintas |
| **Transform** | Aplicar regras de negócio e padronizar formatos |
| **Load** | Carregar no banco de dados de consolidação |

### Ferramentas de ETL
- Microsoft SQL Server Integration Services (SSIS)
- Oracle Data Integrator
- Pentaho Data Integration
- Informatica PowerCenter

### Papel da SQL
A linguagem SQL é utilizada em todas as etapas do processo ETL

## 9. Conclusão

### Recursos Avançados em SQL

| Objeto | Finalidade principal |
|--------|---------------------|
| **Constraints** | Garantir integridade dos dados (NOT NULL, UNIQUE, CHECK) |
| **Views** | Abstrair consultas complexas e controlar acesso |
| **Triggers** | Auditoria e execução automática de regras |
| **Functions** | Cálculos reutilizáveis que retornam um valor |
| **Stored Procedures** | Encapsular processos de negócio completos |
| **MERGE** | Sincronizar tabelas (INSERT/UPDATE condicional) |
| **ETL** | Integrar dados de múltiplas fontes |

### Benefícios da Programação Avançada
- Reutilização de código
- Manutenção centralizada
- Melhor desempenho (menos tráfego aplicação-banco)
- Regras de negócio garantidas independentemente da aplicação]
