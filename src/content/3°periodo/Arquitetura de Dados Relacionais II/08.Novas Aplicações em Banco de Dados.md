# Novas aplicações em Bancos de Dados
## 1. Introdução às Novas Aplicações
- **Contexto**: Bancos de dados são essenciais não apenas para aplicações transacionais, mas também para análise de dados
- **Áreas de aplicação**: Business Intelligence (BI), Data Warehouse, Big Data, Data Mining
- **Frase-chave**: "Dados são o novo petróleo" (Clive Humby, 2006) – dados brutos precisam ser refinados para gerar valor

## 2. Business Intelligence (BI)

### Definição
Ambiente de análise de dados que permite às empresas tomarem melhores decisões, centralizando informações de diferentes formatos e fontes.

### Por que BI agora?
- Hardware mais barato
- Melhor capacidade de processamento de grandes volumes
- Demanda crescente por mão de obra especializada

## 3. Data Warehouse (DW)

### Definição
"Depósitos de dados normalmente possuem esquemas projetados para análise de dados, usando ferramentas OLAP. Os dados são multidimensionais com atributos de dimensão e atributos de medida." (Silberschatz)

### Arquitetura de Ambiente BI

```
Fontes de dados (ERP, CRM, Planilhas, Arquivos) 
         ↓
    ETL (Extract, Transform, Load)
         ↓
    Data Warehouse (DW)
         ↓
    Relatórios | Dashboards | Cubos OLAP
```

### ETL – Extract, Transform, Load

| Etapa | Funcionalidade |
|-------|----------------|
| **Extração (Extract)** | Conectar à origem e ler dados via SQL |
| **Transformação (Transform)** | Tratamento e limpeza de dados; padronização (ex: BRAZIL → BRASIL) |
| **Carga (Load)** | Armazenar dados transformados no DW |

### Modelagem Dimensional

| Conceito | Descrição |
|----------|-----------|
| **Tabela Fato** | Contém medidas numéricas de negócio (ex: receita, lucro) |
| **Tabela Dimensão** | Contém atributos pelos quais as medidas podem ser agregadas (ex: produto, cliente, tempo) |

### Esquemas de Modelagem

| Esquema | Característica |
|---------|----------------|
| **Star Schema (Estrela)** | Tabela fato diretamente ligada às tabelas de dimensão |
| **Snowflake (Floco de neve)** | Tabelas dimensionais podem ser normalizadas |

### Comparação: Modelo Normalizado vs Dimensional

| Característica | Modelo Normalizado (OLTP) | Modelo Dimensional (DW) |
|----------------|---------------------------|-------------------------|
| Objetivo | Evitar redundância | Performance de leitura |
| Estrutura | Muitas tabelas inter-relacionadas | Poucas tabelas (fato + dimensões) |
| Operação típica | INSERT/UPDATE/DELETE | SELECT/agregações |

SELECT produto_id, cliente_id, SUM(valor) as total_vendas

## 5. Big Data

### Definição
Conjunto de soluções e técnicas aplicadas para ingestão, processamento e análise de dados grandes ou complexos demais (imagens, sons, arquivos não estruturados, dados telemétricos).

### Os 5 Vs do Big Data

| V | Significado | Descrição |
|---|-------------|-----------|
| **Volume** | Grande quantidade de dados | Internet: petabytes e exabytes |
| **Variedade** | Diferentes formatos | Estruturados (SQL), semiestruturados (JSON/XML), não estruturados (textos, fotos, vídeos) |
| **Velocidade** | Alta velocidade de geração | Fluxo massivo e contínuo (redes sociais, sensores, telemetria) |
| **Veracidade** | Inconsistências e incertezas | Qualidade e precisão difíceis de controlar |
| **Valor** | Utilidade dos dados | Dados só têm valor quando convertidos em algo útil |

### Arquitetura de Big Data
- Ingestão de dados por **lote** (batch) ou **streaming** (tempo real)
- Computação em nuvem como aliada (elasticidade sob demanda)

### Data Lakehouse
- Novo conceito que combina Data Warehouse e Big Data
- Influenciado por Ralph Kimball

## 6. Data Mining (Mineração de Dados)

### Definição
"Procurar padrões interessantes nos dados – padrões que possam ser usados para definir estratégia de negócio ou identificar comportamento incomum." (Date)

### Principais Técnicas

| Técnica | Descrição | Exemplo |
|---------|-----------|---------|
| **Previsões** | Fazer previsões com base em dados passados e presentes | Análise de tendências de vendas |
| **Associações** | Identificar relações entre variáveis | "Quem comprou A também comprou B" |
| **Clusterização** | Agrupar objetos semelhantes | Segmentação de clientes |

### Ferramentas de Self-Service BI
- Power BI (Microsoft)
- Tableau
- QlikView

## 7. Conclusão

### Evolução das Aplicações de Banco de Dados

| Era | Foco | Característica |
|-----|------|----------------|
| **Tradicional** | OLTP | Processamento transacional (INSERT/UPDATE/DELETE) |
| **BI / DW** | OLAP | Análise de dados e tomada de decisão |
| **Big Data** | 5 Vs | Volume, variedade, velocidade, veracidade, valor |
| **Data Mining** | Padrões | Descoberta de conhecimento em dados |

### Resumo dos Conceitos

| Conceito | Definição |
|----------|-----------|
| **Business Intelligence (BI)** | Ambiente de análise para tomada de decisão |
| **Data Warehouse (DW)** | Armazém de dados com modelagem dimensional |
| **ETL** | Processo de Extração, Transformação e Carga |
| **Star Schema / Snowflake** | Esquemas de modelagem dimensional |
| **Big Data** | Soluções para dados grandes ou complexos |
| **Data Mining** | Busca por padrões interessantes nos dados |
| **Data Lakehouse** | Combinação de DW e Big Data |

### Tendências
- **Cultura de dados**: empresas tomando decisões exclusivamente com base em dados
- **Self-service BI**: ferramentas que democratizam a análise de dados
- **Streaming**: processamento de dados em tempo real
- **Cloud computing**: elasticidade para processamento de grandes volumes
