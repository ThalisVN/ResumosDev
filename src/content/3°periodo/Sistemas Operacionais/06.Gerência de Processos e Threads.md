# Gerência de Processos e Threads

## 1. Conceitos Fundamentais

### 1.1 Os Cinco Gerenciamentos de um SO

| Gerenciamento | Função |
|---------------|--------|
| **Processos** | Criação, exclusão, suspensão, sincronização e escalonamento |
| **Memória** | Alocação, desalocação, segmentação, paginação |
| **Dispositivos de E/S** | Gerenciamento de discos, teclados, mouses, impressoras |
| **Arquivos** | Criação, exclusão, leitura/escrita, diretórios, permissões |
| **Segurança** | Autenticação, controle de acesso, auditoria, antivírus, firewall |

---

### 1.2 Time-Sharing (Compartilhamento de Tempo)

| Aspecto | Descrição |
|---------|-----------|
| **Definição** | Múltiplos usuários compartilham o sistema simultaneamente |
| **Mecanismo** | Cada usuário recebe uma fatia de tempo do processador |
| **Ilusão** | Processador dedicado exclusivamente a cada usuário |
| **Analogia** | Cozinheiro preparando vários pratos ao mesmo tempo |

---

## 2. Modelo e Estrutura de Processos

### 2.1 Definição de Processo

| Conceito | Descrição |
|----------|-----------|
| **Processo** | Instância de um programa em execução |
| **PID** | Process Identifier - número único que identifica cada processo |
| **Localização** | Informações em `/proc` (Linux) |

---

### 2.2 Troca de Contexto (Context Switching)

| Aspecto | Descrição |
|---------|-----------|
| **Definição** | Operação que permite ao SO alternar rapidamente entre processos |
| **Mecanismo** | Salvar estado atual → carregar estado do novo processo |
| **Objetivo** | Cada processo "sente" ter uma CPU virtual exclusiva |

---

### 2.3 PCB (Process Control Block)

| Aspecto | Descrição |
|---------|-----------|
| **Função** | Mantém o contexto de cada processo |
| **Importância** | Permite interromper e retomar processos |

**Contexto de Hardware:**

| Registrador | Função |
|-------------|--------|
| **PC (Program Counter)** | Próxima instrução a ser executada |
| **IR (Instruction Register)** | Instrução atual em execução |
| **SP (Stack Pointer)** | Topo da pilha de memória do processo |
| **MAR (Memory Address Register)** | Endereço para operação de memória |
| **MBR (Memory Buffer Register)** | Dados para operação de memória |
| **AC (Accumulator)** | Operações aritméticas |
| **PSW (Program Status Word)** | Flags de estado da instrução |

**Contexto de Software:**
- Quotas, privilégios, prioridades

---

### 2.4 Tabela de Processos

| Aspecto | Descrição |
|---------|-----------|
| **Definição** | Estrutura centralizada que contém todos os PCBs |
| **Função** | Gerenciar todos os processos em execução |

---

### 2.5 Espaço de Endereçamento

| Conceito | Descrição |
|----------|-----------|
| **Definição** | Conjunto de endereços na memória que o processo pode acessar |
| **Conteúdo** | Instruções, dados, pilha |
| **Ferramenta** | `memstat` - visão detalhada do uso de memória |

---

### 2.6 Descritores de Arquivo (File Descriptors - FDs)

| Conceito | Descrição |
|----------|-----------|
| **Definição** | Referências para arquivos abertos ou recursos de I/O (sockets) |
| **Característica** | Cada processo tem sua própria tabela de descritores |
| **Tabela Global** | Open file table - registra todos os arquivos abertos no sistema |
| **Ferramenta** | `strace` - monitora chamadas de sistema |

---

## 3. Ciclo de Vida de Processos

### 3.1 Estados de um Processo

| Estado | Descrição |
|--------|-----------|
| **Novo** | Processo sendo criado |
| **Pronto** | Aguardando alocação da CPU |
| **Em Execução** | Instruções sendo executadas |
| **Espera (Bloqueado)** | Aguardando evento ou recurso (ex: I/O) |
| **Terminado** | Execução finalizada |

---

### 3.2 Comandos para Visualização de Processos

| Comando | Função | Característica |
|---------|--------|----------------|
| **`ps`** | Snapshot dos processos atuais | PID, usuário, CPU, memória |
| **`top`** | Visão geral dinâmica | Atualização em intervalos regulares |
| **`htop`** | Versão interativa do top | Interface amigável, permite manipular processos |
| **`iotop`** | Foco em operações de I/O | Identifica processos intensivos em I/O |
| **`pgrep`** | Pesquisa processos por nome | Retorna PIDs correspondentes |

---

## 4. Manipulação de Processos

### 4.1 Comandos de Identificação

| Comando | Função |
|---------|--------|
| **`fuser`** | Identifica processos usando arquivo/diretório/socket específico |
| **`lsof`** | Lista todos os arquivos abertos por processos |

---

### 4.2 Controle de Tarefas (Jobs)

| Comando | Função |
|---------|--------|
| **`jobs`** | Lista tarefas iniciadas em segundo plano |
| **`bg`** | Retoma tarefa pausada e move para segundo plano |
| **`fg`** | Traz tarefa do segundo para primeiro plano |

---

### 4.3 Sinais e Teclas de Escape

| Sinal/Tecla | Ação | Descrição |
|-------------|------|-----------|
| **`Ctrl+C`** | SIGINT | Termina execução de forma ordenada |
| **`Ctrl+Z`** | SIGTSTP | Pausa execução e move para segundo plano |
| **`kill`** | Envia sinais | Pausar, continuar, terminar processos |

---

### 4.4 IPC (Inter-Process Communication)

| Técnica | Descrição |
|---------|-----------|
| **Semáforos** | Controlam acesso a recursos compartilhados (previnem condição de corrida) |
| **Pipes** | Comunicação unidirecional entre processos |
| **Filas de Mensagens** | Troca de mensagens estruturadas |
| **Memória Compartilhada** | Região de memória acessível por múltiplos processos |

---

### 4.5 Estados dos Semáforos

| Estado | Significado |
|--------|-------------|
| **Verde (Livre)** | Recurso disponível para acesso |
| **Vermelho (Bloqueado)** | Recurso ocupado; outros processos devem esperar |

---

## 5. Multi-threading

### 5.1 Processos vs. Threads

| Aspecto | Processos | Threads |
|---------|-----------|---------|
| **Definição** | Entidades independentes | Subunidades de um processo |
| **Espaço de Memória** | Próprio e isolado | Compartilhado com outras threads do mesmo processo |
| **Recursos** | Próprios | Compartilhados |
| **Criação** | `fork()` | Bibliotecas de threads |

---

### 5.2 Operação Fork

| Aspecto | Descrição |
|---------|-----------|
| **Função** | Processo pai duplica seu espaço de endereços |
| **Resultado** | Novo processo filho com PID único |
| **Herança** | Filho herda características e recursos do pai |

---

### 5.3 Escalonadores

| Tipo | Função |
|------|--------|
| **Médio Prazo** | Seleciona processos da memória virtual para RAM |
| **Curto Prazo** | Decide qual processo/thread pronto executa a seguir na CPU |

---

## 6. Escalonamento de Processos

### 6.1 Tipos de Processos por Comportamento

| Tipo | Característica |
|------|----------------|
| **I/O-bound** | Passa maior parte do tempo esperando operações de E/S |
| **CPU-bound** | Passa maior parte do tempo usando ativamente a CPU |

---

### 6.2 Tipos de Processos por Criticidade

| Tipo | Prioridade | Característica |
|------|------------|----------------|
| **Real-time** | 1-99 (1 = maior) | Críticos, exigem resposta imediata |
| **Convencionais** | 100-139 (100 = maior) | Tarefas gerais do sistema e aplicativos |

---

### 6.3 Algoritmos de Escalonamento

**Preemptivos (permitem interrupção):**

| Algoritmo | Descrição |
|-----------|-----------|
| **Round Robin (RR)** | Cada processo recebe um quantum de tempo |
| **SRTF** | Shortest Remaining Time First - menor tempo restante primeiro |

**Não Preemptivos (executam até completar ou ceder):**

| Algoritmo | Descrição |
|-----------|-----------|
| **SJF** | Shortest Job First - menor tarefa primeiro |
| **FIFO/FCFS** | First In First Out - primeiro a chegar, primeiro atendido |

---

### 6.4 Comandos de Prioridade

| Comando | Função |
|---------|--------|
| **`nice`** | Inicia processo com prioridade ajustada |
| **`renice`** | Altera prioridade de processo em execução |
| **`ionice`** | Define classe/prioridade de escalonamento de E/S |

---

### 6.5 Comparação: Preemptivo vs. Não Preemptivo

| Critério | Preemptivo | Não Preemptivo |
|----------|------------|----------------|
| **Interrupção** | Permitida | Não permitida |
| **Justiça** | Melhor distribuição de CPU | Pode causar monopólio |
| **Overhead** | Maior (troca de contexto) | Menor |
| **Exemplo** | RR, SRTF | SJF, FIFO |

---

## 7. Monitoramento de Processos

### 7.1 Load Average (Média de Carga)

| Aspecto | Descrição |
|---------|-----------|
| **Definição** | Média de processos executáveis ou não interrompíveis |
| **Intervalos** | 1, 5 e 15 minutos |
| **Comandos** | `uptime`, `top` |

**Interpretação:**

| Valor | Significado |
|-------|-------------|
| Igual ao nº de CPUs | Capacidade total utilizada |
| Acima do nº de CPUs | Sobrecarga |
| Abaixo do nº de CPUs | Ociosidade/subutilização |

---

### 7.2 Estados dos Processos na Média de Carga

| Estado | Descrição |
|--------|-----------|
| **Executável** | Usando CPU ou esperando vez |
| **Não Interrompível** | Esperando I/O (disco, rede) |

---

### 7.3 Ferramentas de Monitoramento

| Ferramenta | Função |
|------------|--------|
| **`top`** | Visão geral dinâmica de processos |
| **`htop`** | Versão interativa |
| **`vmstat`** | Estatísticas de memória virtual |
| **`iostat`** | Estatísticas de I/O |
| **`uptime`** | Média de carga |

---

## 8. Problemas com Gerência de Processos

### 8.1 Deadlock (Impasse)

| Aspecto | Descrição |
|---------|-----------|
| **Definição** | Dois ou mais processos esperando indefinidamente por recursos |
| **Consequência** | Nenhum processo consegue avançar |

**Quatro Condições Necessárias:**

| Condição | Descrição |
|----------|-----------|
| **Exclusão Mútua** | Apenas um processo pode usar recurso por vez |
| **Espera e Retenção** | Processo retém recursos enquanto espera outros |
| **Não Preempção** | Recursos só podem ser liberados voluntariamente |
| **Espera Circular** | Ciclo de dependência entre processos |

---

### 8.2 Estratégias para Deadlock

| Estratégia | Descrição |
|------------|-----------|
| **Prevenção** | Garantir que pelo menos uma condição não ocorra |
| **Detecção e Resolução** | Identificar e abortar processos ou revogar recursos |
| **Ignorar** | Aceitar deadlocks raros (sistemas não críticos) |

---

### 8.3 Starvation (Inanição)

| Aspecto | Descrição |
|---------|-----------|
| **Definição** | Processo incapaz de avançar por ser continuamente superado |
| **Causa** | Políticas desajustadas de alocação de recursos |
| **Exemplo** | Processo de baixa prioridade nunca acessa recurso |
| **Diferença do Deadlock** | Não há ciclo de dependência; sistema continua operando |

---

### 8.4 Comparação: Deadlock vs. Starvation

| Critério | Deadlock | Starvation |
|----------|----------|------------|
| **Causa** | Ciclo de dependências | Políticas de prioridade desajustadas |
| **Visibilidade** | Sistema paralisado | Pode passar despercebido |
| **Processos afetados** | Todos no ciclo | Apenas alguns |
| **Solução** | Quebrar ciclo | Ajustar políticas |

## 10. Conclusão

A gerência de processos e threads é um pilar central dos sistemas operacionais, abrangendo:

- **Estrutura de processos**: PCB, PID, espaço de endereçamento, descritores de arquivo
- **Ciclo de vida**: Estados (novo, pronto, execução, espera, terminado)
- **Manipulação**: Comandos de visualização, controle e sinais
- **Multi-threading**: Threads como subunidades que compartilham memória
- **Escalonamento**: Algoritmos preemptivos (RR, SRTF) e não preemptivos (SJF, FIFO)
- **Tipos de processos**: I/O-bound vs. CPU-bound; real-time vs. convencionais
- **Monitoramento**: Load average e ferramentas de análise
- **Problemas**: Deadlock (4 condições) e Starvation (inanição)

O domínio desses conceitos permite otimizar o desempenho do sistema, garantir justiça na distribuição de recursos e prevenir paralisações críticas.
