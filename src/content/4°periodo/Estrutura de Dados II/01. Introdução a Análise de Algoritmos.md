## 1. Introdução

- **Objetivo do capítulo**: apresentar os conceitos fundamentais de algoritmos, recursividade, complexidade computacional e eficiência.
    
- **Algoritmo**: processo sistemático para resolver um problema, transformando uma entrada de dados em uma saída.
    
- **Correção**: verifica se o algoritmo produz o resultado esperado, podendo ser demonstrada por prova matemática.
    
- **Análise**: avalia a eficiência do algoritmo em relação ao tempo de execução e à memória utilizada.
    
- **Estruturas de dados**: formas de organizar e manipular dados segundo determinadas regras, permitindo representar modelos e implementar operações computacionais.
    
- **Relação entre algoritmos e estruturas de dados**: a escolha de uma estrutura deve considerar os algoritmos utilizados para manipulá-la e a eficiência dessas operações.
    

## 2. Apresentação dos Algoritmos

### Definição

Os algoritmos são apresentados por meio de uma linguagem simplificada, semelhante ao Pascal, com o objetivo de facilitar a leitura e a compreensão da lógica de programação.

### Principais convenções

| Elemento               | Significado                                           |
| ---------------------- | ----------------------------------------------------- |
| `:=`                   | Atribuição de valor a uma variável                    |
| `se... então`          | Execução condicional                                  |
| `se... então... senão` | Decisão entre alternativas                            |
| `enquanto... faça`     | Repetição enquanto uma condição for verdadeira        |
| `para... faça`         | Repetição controlada por uma variável                 |
| `pare`                 | Interrupção de uma execução ou estrutura de repetição |
| `A[i]`                 | Elemento de um vetor identificado por índice          |
| `T.chave`              | Campo de um registro                                  |
| `↑`                    | Referência a um registro por meio de um ponteiro      |
| `%`                    | Indicação de comentário                               |

### Exemplo: inversão de uma sequência

Para inverter um vetor, trocam-se os elementos das extremidades: o primeiro com o último, o segundo com o penúltimo, e assim sucessivamente.

- Utiliza-se uma variável temporária para guardar um dos elementos durante a troca.
    
- O processo é realizado até a metade do vetor.
    
- Para uma sequência de tamanho (n), são realizadas aproximadamente (n/2) trocas.
    

**Ideia principal:** um algoritmo deve apresentar uma sequência organizada de instruções para resolver o problema proposto.

## 3. Recursividade

### Definição

A **recursividade** ocorre quando um procedimento ou função chama a si mesmo durante sua execução.

- **Chamada recursiva**: chamada feita pelo próprio procedimento.
    
- **Chamada externa**: chamada iniciada fora do procedimento.
    
- **Caso-base**: condição que encerra a recursão, evitando chamadas indefinidas.
    

### Vantagens e desvantagens

| Aspecto          | Descrição                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| **Vantagens**    | Pode produzir soluções mais simples, concisas e próximas da definição matemática do problema.     |
| **Desvantagens** | Pode exigir mais memória e apresentar menor eficiência que uma solução não recursiva equivalente. |
| **Alternativa**  | Implementação iterativa, utilizando estruturas de repetição.                                      |

### Exemplo 1: cálculo do fatorial

O fatorial de um número inteiro não negativo é definido por:

[  
n! = n \times (n-1)!  
]

Para (n>0), com a condição inicial (0!=1).

Exemplo:

[  
5! = 5\times4\times3\times2\times1=120 ]

- **Versão recursiva**: calcula o fatorial chamando a função para o número anterior.
    
- **Versão não recursiva**: utiliza repetição para calcular os fatoriais progressivamente.
    

Ambas podem apresentar complexidade de tempo (O(n)), embora tenham diferenças no uso de memória.

### Exemplo 2: Torre de Hanói

O problema consiste em transferir discos entre três pinos, respeitando duas regras:

1. Mover apenas um disco por vez.
    
2. Nunca colocar um disco maior sobre um menor.
    

A solução recursiva para (n) discos envolve:

1. Transferir os (n-1) discos superiores para o pino auxiliar.
    
2. Mover o maior disco para o destino.
    
3. Transferir os (n-1) discos restantes para o destino.
    

O problema demonstra como uma tarefa complexa pode ser dividida em problemas menores. O número mínimo de movimentos é (2^n-1), e a complexidade de tempo é exponencial, (O(2^n)).

## 4. Complexidade de Algoritmos

### Definição

A complexidade mede os recursos necessários para executar um algoritmo, principalmente o **tempo de execução** e o **espaço de memória**.

A análise pode ser feita por dois métodos:

- **Empírico**: executa o algoritmo e mede o tempo observado.
    
- **Analítico**: estuda matematicamente o comportamento do algoritmo, independentemente do computador, da linguagem e do compilador utilizados.
    

### Conceitos fundamentais

- **Tamanho da entrada ((n))**: quantidade de dados processados.
    
- **Passo**: unidade de execução formada por operações básicas.
    
- **Operação dominante**: operação executada com maior frequência e utilizada como referência na análise.
    
- **Comportamento assintótico**: comportamento do algoritmo quando o tamanho da entrada cresce.
    

### Tipos de complexidade

|Tipo|Definição|Objetivo|
|---|---|---|
|**Melhor caso**|Menor número de passos entre as entradas consideradas|Avaliar a situação mais favorável|
|**Caso médio**|Número esperado de passos, considerando as probabilidades das entradas|Avaliar o comportamento esperado|
|**Pior caso**|Maior número de passos entre as entradas consideradas|Estabelecer um limite superior para a execução|

O pior caso é bastante utilizado porque permite avaliar o comportamento do algoritmo diante da entrada mais desfavorável.

### Exemplos de complexidade

|Problema ou algoritmo|Número de passos|Complexidade|
|---|---|---|
|Operação com quantidade fixa de passos|Constante|(O(1))|
|Inversão de um vetor|Aproximadamente (n/2) trocas|(O(n))|
|Cálculo iterativo do fatorial|Proporcional a (n)|(O(n))|
|Soma de duas matrizes (n\times n)|(n^2) operações|(O(n^2))|
|Multiplicação de matrizes pelo algoritmo apresentado|(n^3) operações|(O(n^3))|
|Torre de Hanói|Crescimento exponencial|(O(2^n))|

## 5. Notações Assintóticas

### Definição

As notações assintóticas descrevem como a complexidade de um algoritmo cresce à medida que o tamanho da entrada aumenta. Elas permitem comparar algoritmos sem depender de constantes específicas de execução.

### Principais notações

|Notação|Significado|Interpretação|
|---|---|---|
|**O (Big O)**|Limite superior assintótico|A função cresce no máximo na ordem indicada, a menos de uma constante|
|**Ω (Ômega)**|Limite inferior assintótico|A função cresce pelo menos na ordem indicada, a menos de uma constante|
|**Θ (Teta)**|Limite assintótico justo|A função possui a mesma ordem de crescimento da função de referência|

### Simplificação das expressões

Na análise assintótica, desprezam-se constantes multiplicativas, constantes aditivas e termos de menor ordem.

Exemplos:

|Expressão original|Forma assintótica|
|---|---|
|(3n+5)|(O(n))|
|(n^2+n)|(O(n^2))|
|(6n^3+4n-9)|(O(n^3))|
|(403)|(O(1))|

### Comparação das ordens de crescimento

Em geral, quando (n) aumenta, algoritmos com crescimento linear ou quadrático tendem a ser mais eficientes do que algoritmos com crescimento exponencial, considerando o mesmo problema e condições comparáveis.

- **(O(1))**: constante.
    
- **(O(\log n))**: logarítmica.
    
- **(O(n))**: linear.
    
- **(O(n^2))**: quadrática.
    
- **(O(n^3))**: cúbica.
    
- **(O(2^n))**: exponencial.
    

A notação assintótica é importante para identificar soluções que continuam viáveis quando o volume de dados cresce.

## 6. Algoritmos Ótimos

### Definição

Um **algoritmo ótimo** é aquele cuja complexidade alcança o melhor limite de eficiência possível para resolver determinado problema, considerando os limites inferiores conhecidos.

### Limite inferior

O limite inferior indica o mínimo de trabalho que qualquer algoritmo precisa realizar para resolver um problema, expresso por meio da notação (\Omega).

Por exemplo, para inverter uma sequência de (n) elementos, é necessário considerar os elementos da entrada. Assim, existe um limite inferior de ordem (\Omega(n)).

### Exemplos apresentados no capítulo

|Problema|Complexidade do algoritmo|Conclusão|
|---|---|---|
|Inversão de uma sequência|(O(n))|Ótimo, considerando o limite inferior (\Omega(n))|
|Soma de matrizes (n\times n)|(O(n^2))|Ótimo, considerando o limite inferior (\Omega(n^2))|
|Multiplicação convencional de matrizes|(O(n^3))|Não é ótimo segundo os algoritmos mais eficientes mencionados no texto|
|Ordenação por algoritmos de ordem (O(n\log n))|(O(n\log n))|Ótimos quando se considera o limite inferior correspondente para ordenação por comparações|

**Importante:** a complexidade de um algoritmo, isoladamente, não comprova sua otimalidade. É necessário compará-la com um limite inferior do problema.

O capítulo 1 apresenta os fundamentos necessários para estudar algoritmos e estruturas de dados. Inicialmente, diferencia correção e análise, explica a representação dos algoritmos e introduz a recursividade por meio de exemplos como o fatorial e a Torre de Hanói.

Em seguida, apresenta a complexidade computacional e as formas de avaliar o desempenho de um algoritmo em relação ao tempo e à memória. As notações (O), (\Omega) e (\Theta) permitem descrever o crescimento dos custos de execução, enquanto o conceito de algoritmo ótimo relaciona a eficiência alcançada aos limites inferiores do problema.

O conhecimento desses conceitos é essencial para escolher estruturas de dados e desenvolver algoritmos corretos, eficientes e adequados ao volume de informações processadas.
