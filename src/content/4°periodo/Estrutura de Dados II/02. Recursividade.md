## Fundamentos da Recursão

A **recursão** é um método de resolução de problemas que consiste em  
decompor um problema em subproblemas semelhantes, porém cada vez mais  
simples. Quando os subproblemas se tornam triviais, eles são resolvidos  
diretamente. Em seguida, suas soluções são combinadas, na ordem inversa  
à decomposição, até que se obtenha a solução do problema inicial.

### Exemplo: arrecadação de uma doação

Para arrecadar R$ 700,00, imaginando que cada pessoa possa doar R$  
100,00, uma pessoa pode contribuir com R$ 100,00 e pedir a duas outras  
pessoas que arrecadem R$ 300,00 cada. Essas pessoas podem repetir a  
estratégia, até que os valores sejam pequenos o suficiente para serem  
doados diretamente. O exemplo ilustra como um problema maior pode ser  
dividido em outros menores.

## 2. Base e Passo de Recursão

Em programação, a recursão é implementada por **funções recursivas**,  
isto é, funções que chamam a si mesmas. Uma função recursiva deve ter  
duas partes fundamentais:

- **Base de recursão:** resolve diretamente um caso trivial do  
    problema, encerrando a sequência de chamadas.
- **Passo de recursão:** resolve um caso geral transformando-o em um  
    problema semelhante, mas mais simples, e usando uma chamada  
    recursiva para obter sua solução.

A estratégia recursiva segue três etapas:

1. Transformar o problema `P` em um problema semelhante e mais simples,  
    `Q`.
2. Obter a solução de `Q` por meio de uma chamada recursiva.
3. Usar a solução de `Q` para compor a solução de `P`.

A cada chamada, o problema deve ficar mais simples. Quando se alcança um  
caso trivial, termina a decomposição e começa a composição das soluções.  
Se a função não simplificar o problema ou não reconhecer os casos  
triviais, poderá entrar em um ciclo de chamadas sem chegar a uma  
solução.

## 3. Funções Recursivas

### 3.1. Cálculo de fatorial

O fatorial de um inteiro não negativo `n`, representado por `n!`, é  
definido por:

- `0! = 1`
- `n! = n × (n − 1)!`, para `n > 0`

O caso `n = 0` é a base da recursão. Para valores maiores que zero, a  
função calcula o fatorial de um valor menor e multiplica o resultado por  
`n`.

Exemplo de implementação em C, conforme o material:

```
int fat(int n) {
    if (n == 0)
        return 1;
    else
        return n * fat(n - 1);
}
```

Para calcular `fat(4)`, as chamadas são decompostas até `fat(0)`.  
Depois, os resultados são combinados:

`fat(4) = 4 × fat(3) = 4 × 3 × fat(2) = 4 × 3 × 2 × fat(1) = 4 × 3 × 2 × 1 × fat(0) = 24`

O funcionamento possui duas fases:

- **Decomposição:** as chamadas recursivas continuam até alcançar o  
    caso trivial.
- **Composição:** os resultados são devolvidos e as operações que  
    ficaram pendentes são executadas.

As operações pendentes são controladas por uma **pilha**. Se houver  
chamadas recursivas demais para a capacidade disponível, a execução pode  
terminar com um erro de pilha cheia (_stack overflow_).

### 3.2. Exibição de números em binário

Uma função do tipo `void` também pode ser recursiva, mesmo sem devolver  
um valor. Nesse caso, as chamadas produzem efeitos que, em conjunto,  
formam o resultado final.

Para exibir um número natural `n` em binário:

- Se `n < 2`, basta exibir o próprio número.
- Caso contrário, exibe-se recursivamente o binário da metade inteira  
    de `n` e, depois, o resto da divisão inteira de `n` por `2`.

A ideia é reduzir o número a cada chamada. Por exemplo, para converter  
`13`, a função primeiro trata `13 / 2`, depois os valores menores, até  
chegar a um caso básico; os restos são exibidos na ordem que compõe  
`1101`.

Exemplo de implementação em C:

```
void bin(int n) {
    if (n < 2)
        printf("%d", n);
    else {
        bin(n / 2);
        printf("%d", n % 2);
    }
}
```

### 3.3. Torres de Hanói

As **Torres de Hanói** são um problema com três torres e `n` discos de  
tamanhos distintos. Inicialmente, todos os discos estão na torre de  
origem, organizados do menor no topo ao maior na base. O objetivo é  
transferi-los para a torre de destino, usando a torre auxiliar.

As regras são:

- Mover apenas um disco por vez.
- Nunca colocar um disco sobre outro menor.
- Mover os discos diretamente de uma torre para outra.

A estratégia recursiva para `n` discos é:

1. Mover recursivamente `n − 1` discos da origem para a torre auxiliar,  
    usando o destino como apoio.
2. Mover diretamente o disco restante da origem para o destino.
3. Mover recursivamente os `n − 1` discos da torre auxiliar para o  
    destino, usando a origem como apoio.

O caso trivial ocorre quando há apenas um disco: ele pode ser movido  
diretamente para a torre de destino. O problema maior é, assim,  
resolvido por duas transferências menores e um movimento direto.

## 4. Recursão Degenerada

A recursão pode tornar a lógica de um algoritmo mais simples e concisa,  
mas essa vantagem nem sempre compensa o custo das chamadas recursivas.

### 4.1. Recursão de cauda

A **recursão de cauda** ocorre quando a função faz uma única chamada  
recursiva no final e não há instruções da função que precisem ser  
executadas depois que essa chamada terminar. Nesse caso, a chamada  
recursiva serve essencialmente para repetir o processamento.

Um exemplo apresentado no material é a contagem regressiva de `n` até  
`0`:

- Se `n < 0`, não é necessário fazer nada.
- Caso contrário, exibe-se `n` e chama-se recursivamente a função para  
    `n − 1`.

## 5. Conclusão

A recursão resolve problemas por meio de chamadas sucessivas a versões  
menores do mesmo problema. Para funcionar corretamente, uma solução  
recursiva precisa de uma **base de recursão**, que encerra as chamadas,  
e de um **passo de recursão**, que simplifica o problema.

O cálculo de fatorial, a conversão para binário e as Torres de Hanói  
demonstram diferentes formas de aplicar essa técnica. Durante a  
execução, a recursão passa por uma fase de decomposição e outra de  
composição, e as chamadas pendentes utilizam uma pilha. Por isso, embora  
possa simplificar a solução, a recursão deve ser usada considerando seus  
custos e o risco de exceder a capacidade da pilha.
